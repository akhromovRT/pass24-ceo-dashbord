# Правила работы над проектом

## Описание проекта и целей пользователя

- Проект: **CEO24** — управленческая информационная система для ООО «ОНВИ СЕРВИС»
- Назначение: Аналитика в реальном времени по биллингу абонентской платы, воронке продаж и сводный дашборд CEO
- Цели: Заменить ручной анализ Excel-выгрузок, контролировать оплаты и должников, прогнозировать MRR/ARR, сверять заявки менеджеров с 1С
- Как используется: Веб-приложение для CEO, руководителя продаж, менеджеров и бухгалтера (5 пользователей, 274 клиента)
- Контекст: B2B-компания, продающая системы контроля доступа PASS24. Рекуррентная выручка (~50%) + проектная (оборудование). 1С — master-система финансов. CEO24 добавляет управленческий слой поверх бухгалтерских данных
- Стек: Python 3.12 + FastAPI + SQLModel + PostgreSQL 16 | Vue 3 + TypeScript + PrimeVue + vue-echarts | Docker
- Текущая фаза: MVP (6 недель) — парсер 1С, API, реестр клиентов, просрочки, базовый дашборд

## Назначение AGENTS.md и границы

- AGENTS.md содержит только универсальные правила, применимые ко всем задачам.
- Специфические инструкции хранить в профильных документах `agent_docs/` или уточнять у пользователя; не раздувать AGENTS.md.
- Все проектные документы хранить в `agent_docs/`, кроме `README.md`, `AGENTS.md` и `CLAUDE.md`.

## При начале работы над задачей

- Прочитать блок "Описание проекта и целей пользователя".
- Прочитать последние 10 записей `agent_docs/development-history.md`.
- По карте документов `agent_docs/index.md` открыть только релевантные файлы.
- При нехватке контекста задать вопросы пользователю.

## Источники данных

Три входных файла из 1С/банка:

1. **Задолженность покупателей** (XLS/XLSX) — основной. 3-уровневая иерархия: Покупатель (ИНН) → Договор → Документ (Реализация/Поступление). Содержит: долг начало/конец, аванс начало/конец, продано, оплачено, предоплата поступила/зачтена.
2. **Банковская выписка** (XLSX) — плоский список входящих платежей: дата, контрагент, ИНН, сумма, назначение платежа (содержит номер счёта, период, договор).
3. **Аналитика поступлений** (XLSX, 5 листов) — текущий ручной инструмент для замены:
   - «План vs Факт» — помесячные план/факт по каждому клиенту с метаданными (объект, тип, адрес, ссылка на облако)
   - «Должники» — список должников с месяцами неоплаты
   - «Детализация платежей» — каждый платёж с датой, суммой, назначением
   - «Денежный поток» — агрегаты план/факт подписок + прочие
   - «Прочие поступления» — непод писочная выручка

## Универсальные правила

- Следовать существующим паттернам, правилам и соглашениям проекта.
- Не использовать AGENTS.md как стайлгайд или список команд; для стиля полагаться на линтеры/форматтеры и существующий код.
- Документы держать краткими; вместо копирования кода ссылаться на файлы и модули.
- Если планируются большие изменения — сначала кратко согласовать подход.
- Обновлять затронутую документацию.

## Чек-лист перед завершением задачи

- Проверить, что выполнены требования задачи и изменения соответствуют ожидаемому поведению.
- Обновить релевантные документы и при необходимости запись в `agent_docs/development-history.md`.
- Если принято важное решение — добавить запись в `agent_docs/adr.md`.
- Свериться с `agent_docs/guides/dod.md` и убедиться, что критерии DoD выполнены или зафиксированы причины.
- Зафиксировать причины, если тесты не запускались или не добавлены новые (если это ожидается).
